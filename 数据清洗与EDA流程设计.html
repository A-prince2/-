01清洗顺序：为什么不能随便调

清洗步骤的先后顺序会直接改变结果，这不是风格问题。整个流程固定为六步：

顺序步骤为什么必须在这个位置
1列名标准化后面所有逻辑都依赖标准列名。先做映射，代码才不和你这一份数据绑死
2类型转换必须早于去重和异常值。「89」和「89.0」在字符串里是不同的值，不转类型去重会漏；不转数值算不了分位数
3去重去重要用业务键判断，而业务键里的面积/租金必须已经是数值形式才能可靠比较
4缺失值要在算分位数之前处理。NaN 会污染分位计算，让阈值失准
5异常值用清洗过缺失的数据算分位，阈值才干净。放在最前会把脏数据也当基准
6派生特征单价依赖清洗后的租金额面积，面积分箱依赖清洗后的面积

最常见的错误是先删异常值再去重——删完之后你判断不出哪些是重复挂牌，而重复房源本身会让分位数偏移，等于用脏数据定标准。

02五个清洗环节的实现要点

1类型转换：先解析，再计算

租房数据的数值列几乎都是字符串：「3200元/月」「89.5㎡」「1,200」「面议」。核心是用正则抽数字，并让解析失败的值变成 NaN 而不是抛异常。

# 关键：errors="coerce" 保证一条"面议"不会让整列转换崩掉
df["rent"] = pd.to_numeric(
    df["rent"].astype(str)
        .str.replace(",", "", regex=False)          # 千分位
        .str.extract(r"(\d+(?:\.\d+)?)")[0],
    errors="coerce"
)

户型「2室1厅1卫」要拆成三个数值字段，楼层「中楼层/共18层」要拆成所在层与总层。原始串必须保留——解析规则改了可以重跑，原始信息丢了就没得改。

一个真实的坑：楼层提不出具体数字是正常的

很多租房数据的楼层字段只有「中楼层/共18层」这种相对描述，能提出总层数，但提不出"第几层"。这时不要强行把"中"映射成 9 —— 那是在造数据。

脚本的处理是：floor 留空，total_floor 正常提取，并在缺失率超阈值时明确提示"这是正常现象"。我测试时这个字段确实被丢弃了，属于预期行为。

2去重：两层，别只做 drop_duplicates

drop_duplicates() 只能去掉所有字段完全相同的行（采集翻页重叠造成的）。真正麻烦的是同一房源被多个中介挂牌——ID 不同、描述略异，但实体是同一套房。

# 第二层：用业务键判断疑似重复房源
DUP_KEY = ["community", "area", "layout_raw", "rent"]
df = (df.assign(_miss=df[DUP_KEY].isna().sum(axis=1))   # 缺失最少者优先保留
        .sort_values("_miss")
        .drop_duplicates(subset=DUP_KEY, keep="first")
        .drop(columns="_miss"))

注意这层结果是"疑似"，不是"确定"。同一小区、同面积、同户型、同租金，也可能是真的两套房子（比如同栋楼上下层）。稳妥做法是保留这个清单人工看几眼，同时在报告里写明去重规则，让评审知道你是怎么判断的。

3缺失值：分三级，不要一刀切

情况处理理由
缺失率 > 30%丢弃整列信息量太低，填出来的值基本等于编造
核心字段缺失
（租金、面积）		删该行没有租金或面积，这条记录无法进入任何分析，补不出来
其余低缺失数值填中位数
类别填「未知」		租金右偏，均值被高价房拉高，用均值填充会系统性高估

4异常值：必须按商圈判断，不能用全城口径

这是全篇最重要的一条。"异常"不等于"错误"——核心地段的大户型高价房在全城分布里是极端值，但按它所在的商圈看完全合理。用全城 1% 分位过滤，删掉的多半是真实的贵房子。

# 按商圈分组算 1%/99% 分位；样本量太小的商圈退回全城口径
size = df.groupby("business_area", observed=True)["unit_price"].transform("size")
lo_g = df.groupby("business_area", observed=True)["unit_price"].transform(
    lambda s: s.quantile(0.01))
lo = lo_g.where(size >= 10, df["unit_price"].quantile(0.01))   # 小分组退回全城

另外两条规则：

  • 业务硬规则优先：面积小于 5㎡、租金小于等于 0，这种不用算分位，直接判为录入错误或钓鱼房源。
  • 剔除的样本要留档：脚本会把被删的记录导出到 data/outliers_removed.csv。这是自我保护——万一阈值调错了，能倒回去看删了什么。

为什么用分位不用 3σ：租金是右偏分布，标准差被长尾撑大，用 3σ 反而会放过真正的异常值、同时误伤正常的贵房源。分位数对偏态分布更稳健。

5派生特征：为后面的分析问题铺路

  • unit_price = rent / area — 全部横向比较的核心指标，没有它 Q1–Q3 都做不了。
  • room / hall / bath — 从户型串拆出，进入建模。
  • floor_ratio = floor / total_floor — 比绝对楼层有解释力：18 层里的 5 层，和 5 层里的 5 层不是一回事。
  • area_bin — 用固定业务区间（30/60/90/120）而不是等频分箱。因为"90㎡"在租房市场是自然分界，评审一眼能懂。
elevator 的三态处理

电梯转成 boolean 后，缺失值是 NA 而不是 False。"不清楚有没有电梯"和"确认没电梯"是两回事，分析时不要图省事用 fillna(False) 合并——那会把未知混进"无电梯"组，直接影响 Q2 的溢价结论。

03EDA 五个维度与业务含义

每个维度都对应项目方案里的一个业务问题，不做无目的的图表堆砌。

维度做什么对应问题业务含义（这张表说明什么）
1 单变量描述 describe + 偏度 + 峰度 + 变异系数，看分布形状 前置判断 偏度大于 1 说明右偏，此时必须报中位数而不是均值。租金、单价基本都是右偏，报均值会让数字虚高。变异系数用来比较不同单位的离散程度
2 分区位统计 按区县聚合房源数、中位单价、四分位、离散度 Q1 空间格局 中位单价排序就是租金梯度，回答"哪个区贵"。离散度比均值更有信息量——离散度高说明该区内部分化大，只看区均值会掩盖板块差异
3 商圈价格带 按商圈算 P25 / 中位 / P75，过滤小样本 Q3 性价比基准 这是"合理价格带"的定义方式。P25 以下即为同商圈内的折价房源候选。样本少于 10 条的商圈价格带不可信，分位数会被个别极端值带跑
4 类别分组 按装修/朝向/电梯/面积段分组，算组内中位单价与占比 Q2 属性溢价 看结构占比与组间差异。但这里的中位单价差 ≠ 溢价幅度——装修好的房源往往面积更大、区位更好，直接比较混淆了多个因素。真正的溢价要用回归控制变量后再算
5 相关性与散点 数值列相关矩阵 + 面积对单价散点 Q4 规模效应 面积与单价若呈负相关，说明大房子单位面积更便宜，这是"性价比拐点"存在的前提。散点图用来目视确认是否线性，非线性就该分段看而不是硬套相关系数
6 交叉分布 区县 × 面积段 房源数交叉表 补充解释 某区在特定面积段房源特别集中，说明供给结构单一。这能解释该区租金特征的成因，是从"是什么"走向"为什么"的一步

维度之间的递进关系

这六个维度不是并列的，是有顺序的：

  • 先看单变量——不知道租金右偏，后面所有比较都会用错统计量。
  • 再看区位——区位是租金的第一解释变量。不先固定区位，后面比较任何属性都是混淆的。
  • 然后才是属性——在商圈内部比较装修、电梯才有意义。跨区比装修，比的其实是地段。
  • 最后是关系——相关性、交叉表用来生成假设，为正则的建模阶段做准备。

这个顺序本身就是一条论证链：租金差异主要来自区位 → 控制区位后还剩什么差异 → 这些差异来自哪些属性 → 属性能否预测租金。写进报告时按这条链组织，比按图表类型罗列强得多。

04清洗日志：最容易被忽略的加分项

脚本会自动生成 data/cleaning_log.csv，记录每一步清洗前后的行数与删除原因。实际输出长这样：

step,rows_before,rows_after,rows_removed,note
类型转换,254,254,0,
去重·完全重复行,254,251,3,
去重·房源业务键重复,251,248,3,键=community+area+layout_raw+rent
缺失值·删核心字段缺失行,248,245,3,"核心列=['rent', 'area']"
缺失值·填充其余字段,245,245,0,数值取中位数，类别填'未知'
异常值·业务硬规则,245,243,2,面积<5㎡ 或 租金<=0
异常值·单价分位过滤,243,223,20,按 business_area 分组 1%/99% 分位

为什么这东西值钱：它让你的清洗过程可对账。评审或面试官看到这张表，能立刻判断你懂不懂数据——删了 20 条是因为分位过滤，而不是"感觉这些数据不对就删了"。绝大多数求职者的作品集里只有干净的最终结果，没有过程记录。

建议直接把这七行放进报告的「数据清洗」章节，配一句话说明：原始 254 条，清洗后 223 条，保留 87.8%，每一步剔除原因见下表。

05六个实测踩到的坑

下面每一条都是我在跑这份脚本时真实遇到并修掉的，不是从文档里抄的：

坑现象解法
SettingWithCopyWarning 布尔索引筛完再赋值，pandas 报黄色警告，结果不确定 df = df[~bad].copy() —— 筛完立刻 copy，不要依赖视图
中文列名 + query .query("房源数 >= 10") 直接报错 改用布尔索引 ba[ba["房源数"] >= 10]。别和 pandas 的表达式解析器较劲
corr 的版本差异 df.corr(numeric_only=True) 在 pandas 1.3 报 TypeError 先选数值列再 corr()，兼容所有版本
groupby 默认丢 NA 电梯分组后占比加起来不到 100%，看着像数据丢了 加 dropna=False，让"未知"作为独立一组显示出来
中文乱码 Excel 打开 CSV 中文全变方块 存盘统一 encoding="utf-8-sig"
matplotlib 中文变方块 图表标题全是空心方块 设置 font.sans-serif = ["Microsoft YaHei"] 与 axes.unicode_minus = False
别做的事

不要为了让数据"看起来干净"去手工改 CSV。任何清洗都必须由代码从原始数据重新生成，否则过程不可复现，评审一旦要求你重跑就露馅了。

不要静默删除大量数据。如果某一步删掉了超过 15% 的记录，先停下来想想为什么——通常是阈值设错了，或者把"极端但真实"当成了"异常"。
