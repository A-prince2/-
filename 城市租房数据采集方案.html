城市租房数据采集方案

配套「城市租房数据集分析」项目的采集层设计：数据源取舍、字段口径、requests + bs4 框架思路、合规边界与 CSV 落盘。

技术栈 requests · bs4 · csv 目标规模 2000–5000 条 定位 学习研究用途

00先说结论

我在动手前实测了目标站点的 robots 协议，结果直接决定了方案结构，必须先讲清楚：

实测结果

lianjia.com/robots.txt 的结尾是 User-agent: * + Disallow : /*——对所有未单独列出的爬虫（也就是你自己写的脚本）禁止抓取全站。

而贝壳、安居客、58 同城等平台在用户协议中普遍禁止未经许可的自动化采集，并配合验证码与风控。这类站点不是"能爬但慢一点"的问题，而是从协议层面就不允许。

所以本方案走双轨制，两条线的目的不同：

主线 · 用于分析

公开数据集导入

直接使用许可清晰的现成数据集（CC0 / 平台公开），零合规风险、可复现、评审能直接跑通。分析项目真正的主体数据走这条线。

辅线 · 用于展示能力

离线页面解析练习

把页面另存为本地 HTML，用 bs4 做解析与字段抽取练习，全程零网络请求。既练了技术，又不触碰任何协议红线。

为什么这么设计：面试官问"数据怎么来的"，答"用了和鲸 CC0 数据集，并设计了可复用的解析框架"是站得住的；答"我爬了链家"则要面对"你看过它的 robots 吗"这一问。前者是加分，后者是风险敞口。技术上你学到的东西完全一样——requests 与 bs4 的核心能力都在解析层，不在"能不能拿到页面"。

数据时效问题（务必处理）

和鲸与未来杯的数据均为 2019–2020 年，距今已有数年。直接拿来做"当前租金市场分析"会被追问"数据过时"。

两个处理办法：一是把项目明确定位为"历史快照分析"，标题与结论都不写"当前"；二是若能找到两期数据，改做跨期对比（如 2020 vs 2024 租金结构变化），时效劣势反而变成分析亮点。后者更适合写进简历。

1.2 备选：自主采集（仅限 robots 允许的站点）

如果你确实需要新鲜数据来体现采集能力，按以下顺序筛选目标，不要跳过第 0 步：

  • 第 0 步 · 查协议：浏览器打开 目标站域名/robots.txt，找到 User-agent: * 段落。若存在 Disallow: / 或你要抓的路径被禁，放弃该站点，不要用改 UA 的方式绕。
  • 第 1 步 · 查条款：翻一遍用户协议中"禁止自动化访问 / 数据抓取"的条款。有明确禁止即视为不授权。
  • 第 2 步 · 选替代来源：优先找个人房东信息平台、地方性分类信息站、高校周边租房公告栏类站点——反爬弱、robots 宽松的概率更高。
  • 第 3 步 · 控规模：控制在 2000–5000 条。这个量级做分析完全够用，而请求量越小，对目标站的压力与自身风险都越低。

找不到合规目标也不必勉强。作品集评审看的是分析的完整度，不是"有没有写爬虫"。

02字段清单

字段分三层设计：核心层是分析必需，增强层服务于具体业务问题，元数据层用于追溯与调试。即使走公开数据集，也建议按此清单做一次字段映射——你的分析代码就不必和数据源格式绑死。

2.1 核心字段（分析必需，缺一不可）

字段类型示例说明与解析要点
house_idstr108400001234去重主键。若源站无此字段，用 小区+面积+户型+租金 生成哈希替代
citystr成都多城市数据必采，用于分层聚合
districtstr高新区区县，第一级区位粒度
business_areastr天府长城商圈，Q3 性价比分析的分层基准单位，最重要
rentfloat3200月租金（元）。注意是否含"元/天"，需统一换算
areafloat89.5面积（㎡）。需剥离单位字符串，警惕"89㎡""89平"混写
layout_rawstr2室1厅1卫户型原始串，清洗阶段再拆解

2.2 派生字段（不采集，清洗阶段生成）

字段生成规则用途
unit_pricerent / area租金单价，全部横向比较的核心指标
room / hall / bath正则拆解 layout_raw户型特征，进入建模
area_bin面积分箱（如 30 以下 / 30-60 / 60-90 / 90+）Q4 拐点分析
floor_ratiofloor / total_floor楼层相对位置，比绝对楼层更有解释力

2.3 增强字段（按需采集）

字段类型价值解析难度
communitystr小区名，可做更细粒度聚合低（但同名简称多，需归并）
orientationstr朝向，影响采光溢价低（存在"南北"组合值）
floor_rawstr"中楼层/共18层"，需拆两段中（文本混数字）
decorationstr装修等级，Q2 重要的溢价因子低（等级需映射为序数）
elevatorbool电梯，预期显著影响租金中（常缺失，需按总楼层推断）
list_datedate挂牌日期，可算挂牌时长高（常为相对时间"3天前"，需换算）
tagsstr标签（近地铁/随时看房），可做衍生特征中（多值需拼接）

2.4 元数据字段（必须采集）

  • collect_date — 采集日期。没有这个字段，报告就无法声明数据时效，是硬性要求。
  • source_url — 房源详情页地址。用于追溯与人工校验样本，也是评审验证真实性的依据。
  • source_platform — 数据来源标识。多来源合并时必需。
  • page_no — 采集页码。调试阶段用来定位"哪一页开始出现脏数据"。
不要采集的字段

房东 / 中介的姓名、手机号、微信号、身份证号、照片——这些属于个人信息，受《个人信息保护法》约束，采集需取得单独同意。你的分析用不到它们，采了纯属给自己增加风险。分析只需要房源属性，不需要人的信息。

03requests + bs4 框架思路

核心原则：把"拿数据"和"解析数据"彻底分开。请求层只管拿到 HTML，解析层只管从 HTML 里抽字段，存储层只管落盘。三者解耦后，你可以用本地 HTML 文件喂给解析层反复调试，完全不必反复请求服务器——这既是效率问题，也是礼貌问题。

完整骨架见配套文件 collector_skeleton.py，下面只讲结构与关键决策。

3.1 分层结构

collector/
├── config.py        # 常量集中管理：目标 URL、请求头、间隔、路径、字段顺序
├── fetch.py         # 请求层：会话、超时、重试、限速、状态码判断
├── parse.py         # 解析层：HTML → dict，纯函数，可离线测试
├── storage.py       # 存储层：追加写 CSV + raw 备份
└── main.py          # 编排：翻页循环 + 进度打印 + 异常中断保护

学生项目最容易犯的错是把这些全塞进一个 for 循环里。等到解析出错，你分不清是网络问题、页面结构变了、还是字段抽取写错了。分层是为了让错误有位置。

3.2 请求层：三个必须做的保护

import random, time, requests

def fetch(session, url, retry=3):
    # 1) 每一次请求都要有超时。没有 timeout 的请求可能永久挂住，
    #    调试时会误以为是程序卡死，实际是在等一个永远不来的响应。
    for attempt in range(retry):
        try:
            resp = session.get(url, timeout=(5, 15))
            # 2) 状态码必须显式判断，不要假设 200。
            #    403/429 是明确的"请你停下"信号 —— 遇到就停止，
            #    不要换 UA、换代理重试，那性质就从"抓取"变成"绕过风控"了。
            if resp.status_code == 200:
                return resp
            if resp.status_code in (403, 429):
                print("被限流或拒绝，停止采集"); return None
        except requests.RequestException as e:
            print(f"第 {attempt+1} 次失败: {e}")
            time.sleep(2 ** attempt)   # 3) 退避重试，间隔递增
    return None

间隔控制放在翻页循环里，不要放在函数内部——让它显式可见，将来调参时你能一眼看到自己在请求多少次：

time.sleep(random.uniform(2, 5))   # 随机间隔，避免固定节奏

3.3 解析层：先离线，再联网

这一步是新手最容易卡住的地方，给一条能少走很多弯路的路径：

  • ① 抓一次，存快照。成功请求一页后立刻 resp.text 写入 debug/page_001.html，编码用 resp.encoding = resp.apparent_encoding 兜底。
  • ② 用浏览器打开快照。在快照文件上按 F12 检查元素，而不是在真实网站上——真实页面可能被 JS 改写，快照才是你要解析的那份。
  • ③ 判断是否为动态渲染。若快照里搜不到房源价格，说明数据是 JS 异步加载的，bs4 拿不到，此时应换目标站点而非硬啃（绕过渲染属于增加侵入性，不建议在学习项目中做）。
  • ④ 定列表容器，再遍历子项。结构永远是"找到一个装列表的父元素 → 循环子元素 → 每个子元素里抽字段"，不要写一长串精确到层级的选择器，页面一改就全废。
  • ⑤ 每个字段独立 try。单字段抽取失败返回 None，不要让整条记录崩掉，也不要让异常冒到外层终止翻页。
def parse_page(html, page_no):
    soup = BeautifulSoup(html, "html.parser")
    container = soup.select_one("<列表父元素的 CSS 选择器>")   # TODO: 从快照里自己找
    if not container: return []

    rows = []
    for item in container.select("<单个房源的 CSS 选择器>"):
        row = {"page_no": page_no}
        # 关键：每个字段单独 try，缺失就置 None，绝不让一条脏记录中断整页
        for field, selector in FIELD_SELECTORS.items():
            try:
                node = item.select_one(selector)
                row[field] = node.get_text(strip=True) if node else None
            except Exception:
                row[field] = None
        rows.append(row)
    return rows

注意 FIELD_SELECTORS 用字典配置而不是硬编码二十行 try。页面改版时你只改配置，不改逻辑。

3.4 数值字段的提取

列表页的文字几乎都带单位，统一用正则抽数字，再在清洗阶段换算：

import re

def to_number(text):
    # "3200元/月" -> 3200.0 ; "89.5㎡" -> 89.5 ; "--" -> None
    if not text: return None
    m = re.search(r"\d+(?:\.\d+)?", text.replace(",", ""))
    return float(m.group()) if m else None

3.5 调试节奏建议

阶段做什么通过标准
1 打通只请求第 1 页，print 状态码与响应长度，存 HTML 快照能拿到完整 HTML，编码正常无乱码
2 单字段在快照上只抽 rent 一个字段，print 前 3 条3 条租金与实际页面一致
3 全字段补齐字段字典，抽 1 页，存 CSV 用 Excel 打开看字段对齐、无错列、空值位置合理
4 翻页加翻页循环与间隔，跑到第 3 页就停页数递增正确，无重复数据
5 全量放开页数上限，控制总量 2000–5000 条断点续跑可用，中断后能接着采

不要跳过第 2 步。直接写完整脚本再跑，出错时你面对的是二十个字段同时为空，逐个排查比一开始就单字段验证慢得多。

04采集规范与风险边界

4.1 robots 协议：程序化检查，不靠猜

robots 不是法律，但它是网站明示的授权范围，在司法实践中被作为判断"是否未经授权访问"的重要事实依据。用标准库三行代码就能查，没理由跳过：

from urllib.robotparser import RobotFileParser
from urllib.parse import urlparse

def allowed(url, ua="StudentResearchBot"):
    p = urlparse(url); rp = RobotFileParser()
    rp.set_url(f"{p.scheme}://{p.netloc}/robots.txt")
    rp.read()
    return rp.can_fetch(ua, url)   # False 就别采了

注意 UA 要如实填写。用浏览器 UA 伪装成普通用户去抓，等于隐去真实身份，这是"绕过访问控制"的典型特征，风险远大于直接标明来意。

4.2 频率与规模

请求间隔
2–5 s

随机取值，避免固定节奏。这个间隔对一个学生项目完全够用，一天采千条也就一小时。

总量上限
2000–5000

做分析足够。规模越小，对目标站影响越小，自身风险敞口也越小。

单次时长
≤ 60 min

单次运行不超过一小时，跑完即停，不要挂后台持续采。

并发
1

串行执行。多线程并发会成倍放大服务器压力，学习项目没有任何理由这样做。

4.3 五条红线

不要做的事

① 绕过技术措施。破解加密参数、逆向签名算法、伪造 Cookie 或 Token、用代理池轮换 IP 规避封禁——这些行为直接对应"突破技术保护措施"，性质与普通抓取完全不同。

② 采集个人信息。房东姓名、手机号、微信号、身份证、照片属于《个人信息保护法》规制的个人信息，未经同意采集并存储即构成风险。你的分析用不到，别采。

③ 高频或并发压站。可能影响服务正常运行，涉及《反不正当竞争法》相关条款，也可能触及《刑法》第二百八十五条的边界。

④ 数据商用或二次分发。学习研究用途与商业使用是两回事。原始明细不上传公开仓库，作品集只放聚合结果与代码方法。

⑤ 无视拒绝信号。收到 403/429 或验证码页面时立即停止。继续尝试就是明确的"未经授权"证据。

4.4 写进作品集的合规表述

合规不是负担，主动声明反而是加分项——绝大多数候选人根本想不到这一点。建议在项目 README 里写一段：

数据说明
本分析使用和鲸社区公开数据集（CC0 许可），采集日期为 20XX-XX-XX。
数据仅用于学习研究与作品展示，不用于商业用途，不对外分发原始明细。
项目未采集任何个人身份信息，仅涉及房源属性字段。
如涉及自主采集，均事先核实目标站点 robots 协议与用户条款，串行请求、间隔 2–5 秒，遵守 403/429 停止信号。

05CSV 存储方案

5.1 四个关键参数（不设会踩坑）

参数取值不这么写会怎样
encodingutf-8-sig用 UTF-8 存，Excel 打开中文全是乱码，评审第一眼就减分
newline""Windows 下每行之间多出空行，数据行数翻倍
mode"a" 追加用 "w" 会覆盖，程序中断后前面采的全没了
fieldnames固定常量列表不同记录字段顺序不一致，列会错位
 
import csv, os, json

FIELDS = ["house_id", "city", "district", "business_area",
          "community", "rent", "area", "layout_raw",
          "orientation", "floor_raw", "decoration", "elevator",
          "collect_date", "source_url", "page_no"]

def save_rows(rows, path="data/rent_raw.csv"):
    os.makedirs(os.path.dirname(path), exist_ok=True)
    new_file = not os.path.exists(path)
    # utf-8-sig：带 BOM，Excel 直接双击打开中文不乱码
    # newline=""：不加这个，Windows 下每条记录之间会多一个空行
    with open(path, "a", newline="", encoding="utf-8-sig") as f:
        w = csv.DictWriter(f, fieldnames=FIELDS, extrasaction="ignore")
        if new_file:
            w.writeheader()          # 只在首次写表头
        for r in rows:
            w.writerow({k: r.get(k) for k in FIELDS})

extrasaction="ignore" 这个参数值得留意：解析层多抽了一个字段时，写盘不会报错崩掉。调试阶段字段常变，别让它成为中断原因。

5.2 双份落盘：CSV + raw 备份

建议每次都额外存一份原始 HTML 或原始记录 JSON，理由很实在：解析逻辑写错时，你不需要重新请求服务器，直接用备份重跑解析即可。这既是效率，也是对目标站的基本礼貌。

def save_raw_snapshot(html, page_no, dir_="debug"):
    os.makedirs(dir_, exist_ok=True)
    with open(f"{dir_}/page_{page_no:03d}.html", "w", encoding="utf-8") as f:
        f.write(html)

5.3 断点续采

爬虫跑到一半被打断是常态（网络断、电脑休眠、被封）。最简单的续采方案不需要数据库，记一个进度文件即可：

def load_progress():          # 返回上次完成的页码，没有则从 1 开始
    try:
        with open("data/progress.json", encoding="utf-8") as f:
            return json.load(f).get("last_page", 0)
    except FileNotFoundError:
        return 0

每页写完就更新这个文件。顺序很重要：先落 CSV，再更新进度——反过来的话，中途崩溃会丢掉那一页。
