Portfolio Project · Data Analysis

城市租房数据集分析

面向数据分析 / 数据运营岗位的求职项目方案：以城市租房挂牌数据为对象，完成从数据获取、清洗建模到结论交付的完整分析链路。

项目定位 个人作品集 专业 大数据技术 分析对象 城市租房挂牌数据 产出 分析报告 + 可视化看板 + 预估模型

01项目背景与业务目标

1.1 背景

城市租房市场的信息长期处于分散且不透明的状态。房源分散在多个平台与中介渠道，租金水平受区位、面积、户型、装修、楼层等多重因素共同影响，但市场缺乏公开、量化、可复现的定价参照体系。

这直接导致三方困境：租客难以判断一套房源是"贵"还是"正常"，只能凭个人经验横向比价；房东与中介缺少定价依据，挂高则空置周期拉长，挂低则损失收益；租房平台的运营岗则需要一套可度量房源质量与价格合理性的指标体系，用于房源分层与推荐排序。

本项目以某城市租房挂牌数据为样本，尝试用数据分析方法把"租金是否合理"这一经验判断，转化为可量化、可验证的指标与模型。

1.2 业务目标

Objective 01

建立租金影响因素的量化认知

识别区位、面积、户型、装修、楼层、电梯等属性对租金的影响方向与相对强度，输出影响因子排序，替代"凭感觉判断"。

Objective 02

构建同商圈可比价基线

以商圈 / 板块为单位计算租金单价基准区间，形成"同区位同类型房源的合理价格带"，作为溢价或折价的判断标尺。

Objective 03

识别高性价比房源

基于残差思路构建性价比指标，从挂牌房源中筛出"同等条件下租金显著偏低"的样本，输出可解释的推荐清单。

Objective 04

验证租金可预测性边界

用房源结构化属性建立租金预估基线模型，并明确误差区间，说明仅靠公开属性信息能在多大程度上解释租金差异。

交付对象与用途：租客侧作为选房比价工具；房东 / 中介侧作为挂牌定价参考；平台运营侧作为房源分层与价格异常识别的规则来源。

02项目整体流程架构

项目按"数据获取 → 清洗存储 → 特征工程 → 探索分析 → 建模验证 → 可视化交付 → 结论落地"七个阶段推进，每阶段有明确的产物与验收标准，保证分析过程可复现。

数据获取
确定数据来源与字段口径，完成原始数据采集或公开数据集导入，记录采集时间与字段字典，保证可追溯。
产物：raw 原始数据表 + 字段字典
数据清洗与存储
处理缺失值、重复房源、单位不统一、字段串写、逻辑矛盾与极端异常值；按分层思路落库（原始层 / 明细层 / 汇总层）。
产物：清洗后明细表 + 清洗规则说明文档
特征工程
从原始字段派生分析用特征：租金单价、户型拆解（室 / 厅 / 卫）、楼层相对位置、房龄分段、商圈编码、装修等级映射等。
产物：建模宽表 + 特征说明表
探索性分析（EDA）
分布检验、分组对比、相关性分析，验证数据质量与初步业务假设，形成问题清单与假设清单。
产物：EDA 图表集 + 假设清单
建模与验证
建立租金预估基线模型，对比线性回归与树模型的解释力与误差，输出特征重要性排序与误差分布。
产物：模型评估报告（R² / MAE / 误差区间）
可视化与看板
将核心结论封装为可交互看板：租金热力分布、影响因素贡献、性价比房源榜单、预估工具。
产物：可视化看板 / 交互页面
结论与建议
按租客 / 房东 / 平台三类角色输出差异化结论与可执行建议，明确结论的适用边界。
产物：分析报告 + 结论摘要

技术选型与理由

环节技术选型理由
采集Python（requests / BeautifulSoup）处理公开列表页字段，配合限速与重试，适用于中小规模采集
存储MySQL / SQLite数据量为单机可承载级别，关系型结构便于 SQL 聚合与分层建模

关于技术选型的说明（重要）

单城市租房挂牌数据的量级通常在 万条到十万条，远未达到单机处理瓶颈。本项目采用 pandas + SQL 的单机方案是基于数据量级的合理判断，而非能力缺失；分布式框架以扩展层形式保留，用于展示工程实现能力。这一取舍需在面试与报告中主动说明，避免被理解为"不会大数据组件"。

3.1 数据来源方案

方案来源优点需注意

3.3 数据质量处理策略

  • 重复房源：按"小区 + 面积 + 户型 + 租金"组合键识别疑似重复，保留信息完整度最高的一条，并在报告中说明去重规则。
  • 单位统一：全部换算为"元 / 月"，按日计价数据乘以 30 折算并打标记。
  • 异常值：以商圈内租金单价的 1% / 99% 分位为界，结合业务常识（如面积小于 5㎡、租金低于市场均值 20%）双重校验，异常样本剔除而非截断，保留剔除清单备查。
  • 缺失值：缺失率低于 5% 的数值字段用中位数填充，分类字段单列"未知"类；缺失率高于 30% 的字段不进入建模，仅在描述性统计中说明。

04项目预期分析问题

五个问题按"描述现状 → 诊断成因 → 预测结果 → 指导决策"递进组织，每个问题都对应明确的业务动作，避免只做图表不做判断。

Q1城市租金水平的空间格局如何？各区与商圈的租金梯度差异有多大？
分析口径
以租金单价（元/㎡/月）为核心指标，按区县、商圈两级聚合，计算中位数、四分位区间与离散程度。
方法
分组统计 + 箱线图对比 + 租金热力分布图；用基尼系数或极差比衡量区域间不均衡程度。
产出
区域租金梯度排名、各商圈价格带区间、租金高地与洼地清单。
业务价值
为租客提供区位比价参照；为平台划定高价区与潜力区的运营分区。
Q2哪些房源属性对租金影响最显著？影响幅度如何排序？
分析口径
以租金单价为因变量，面积、户型、装修、楼层、电梯、朝向、商圈为自变量，控制区位变量后比较各属性贡献。
方法
相关性分析筛选变量 → 多元线性回归获取可解释系数 → 随机森林特征重要性交叉验证排序。
产出
影响因素排序表，以及"带电梯溢价约 X%""精装相对毛坯溢价约 X%"等可量化结论。
业务价值
把模糊的"装修好所以贵"转化为具体溢价幅度，可直接用于定价沟通与房源卖点提炼。
Q3如何在同一商圈内客观识别"高性价比"房源？
分析口径
以商圈内同类房源（面积段 × 户型）的租金单价中位数为基准，计算单个房源的价格偏离度，偏离为负且幅度显著者即为候选高性价比房源。
方法
分层基准计算 + 残差法（实际单价 − 模型预估单价）/ 预估单价，输出标准化折价率。
产出
性价比房源榜单，附折价率、可比样本数与主要让价原因推测。
业务价值
可直接转化为面向租客的推荐清单，或作为平台"优质房源"标签的规则基础。
Q4面积与租金的关系是否为线性？是否存在性价比拐点？
分析口径
考察面积与租金单价的关系曲线，检验"面积越大、单价越低"的规模效应是否成立，以及拐点出现的位置。
方法
面积分箱统计 + 局部趋势拟合 + 分段回归识别斜率变化点。
产出
面积—单价曲线图，标注性价比最优面积区间及拐点位置。
业务价值
为租客提供"在哪个面积段花的钱最值"的直接建议，也为合租与整租的决策提供量化依据。
Q5能否仅凭房源公开属性预估合理租金区间？误差有多大？
分析口径
以结构化属性为输入预测月租金，评估模型解释力与误差分布，明确"哪些房源难以被准确估值"。
方法
基线模型（线性回归）对照改进模型（随机森林 / GBDT），以 R²、MAE、MAPE 评估，并用残差分析定位系统性偏差。
产出
模型评估表、实际值 vs 预测值散点图、误差最大的房源类型识别。
业务价值
形成"租金预估器"原型，可回答"这套房挂 X 元是否偏离合理区间"，并诚实界定预测能力的上限。

预期核心结论形态

项目最终应能给出类似以下的判断句，而非罗列图表：租金差异的主要来源是区位而非房源本身条件；在控制商圈后，电梯与装修是溢价最显著的两个属性；面积超过某一区间后单价开始显著下行，该区间即为整租的性价比高点；仅靠公开属性可解释约六到七成的租金波动，剩余部分由房龄、采光、通勤等未观测因素决定。

上述结论中的具体数值需在项目实际跑完后填入，不可预先编造。作品集与面试中出现的任何百分比、R²、样本量，都应能在你的代码和报告中找到对应输出。

05项目局限性说明

主动界定结论的适用边界，是分析可信度的一部分。以下局限需在报告与面试中同步说明，并给出对应的处理方式。

维度局限影响应对
数据代表性 样本来自单一城市、单一或少数平台，且平台房源以中介代理为主 结论向其他城市或个人直租房源外推时失效 报告中明确标注适用范围，不外推至其他城市；对房东直租与中介代理分层讨论
价格口径 挂牌价不等于成交价，实际成交普遍存在议价空间 绝对租金水平可能系统性偏高，溢价幅度估计存在偏差 统一表述为"挂牌租金"；结论侧重相对比较（排序、偏离度）而非绝对水平
变量完整性 通勤距离、学区、房龄、采光、噪音、物业品质等关键因素未被采集 存在遗漏变量偏差，模型系数可能吸收未观测因素，影响因果解读 明确声明结论为相关关系而非因果关系；在残差分析中标注未解释部分的可能来源
数据时效 租房挂牌更新快、下架房源无法追踪，样本为单时点截面数据 无法分析价格调整过程与成交周期，结论具有时点性 在报告中标注采集时间窗；如条件允许，保留两期快照做简单对比
数据规模 数据量为单机可处理级别，不构成严格意义上的"大数据"场景 不能声称具备海量数据处理经验 如实说明量级判断依据，将分布式实现作为扩展层展示，而非包装为主链路
模型能力 采用基线模型，未做严格的时空交叉验证；类别特征编码较粗 模型精度有提升空间，跨时间泛化能力未经充分检验 定位为"预估基线"而非生产级模型；用误差区间代替点估计，避免过度承诺精度
合规边界 采集数据仅限学习研究用途 不可二次分发、不可商用 遵守平台条款与 robots 协议，作品集中仅展示聚合结果与代码方法，不公开原始明细数据

6.2 作品集网站项目简介

PORTFOLIO 城市租房数据集分析

背景｜城市租房市场信息分散、定价缺乏量化参照，租客难以判断房源价格是否合理，房东缺少挂牌定价依据。

做法｜采集并清洗 N 条租房挂牌数据，按"区县—商圈—小区"三级归并区位粒度，派生租金单价、户型拆解、楼层相对位置等分析特征；以分层基准与残差法构建性价比指标，用线性回归与树模型量化各属性对租金的贡献并交叉验证重要性排序；最终以 Pyecharts 搭建包含租金分布、影响因子、性价比榜单与租金预估四个模块的可视化看板。

结果｜识别出区位是租金差异的首要来源，控制商圈后电梯与装修为最显著溢价属性；面积与租金单价存在规模效应拐点，据此给出整租性价比最优面积区间；租金预估模型 R² 达 X.XX，并明确仅凭公开属性可解释约 XX% 的租金波动。

技术栈｜Python（pandas / numpy / scikit-learn）、SQL（MySQL）、Pyecharts、Matplotlib
局限｜样本为单城市单时点挂牌数据，不含成交价与通勤、房龄等关键变量，结论侧重相对比较而非绝对水平与外推。

07面试追问预案

项目写进简历后最可能被追问的方向，提前准备口径比背结论更重要。

追问回答要点
你的数据量只有几万条，为什么不用 Spark / Hadoop？ 先说量级判断：这个规模 pandas 单机处理在秒级到分钟级完成，引入分布式框架没有收益。再说能力边界：清洗逻辑已用 PySpark 实现过一版作为对照，理解了分区、宽窄依赖与 shuffle 的代价。结论是"按量级选工具"。
租金单价怎么算？为什么不直接用租金？ 租金绝对值受面积影响，无法跨房源比较。单价（元/㎡/月）剔除了面积规模效应，才能反映区位与品质溢价。同时说明：分析大面积整租时仍需回看总价，因为租客的真实约束是月付能力。
异常值怎么处理的？会不会把真实的高价豪宅删了？ 说明是双重校验而非单一阈值：分位数规则 + 业务常识（低价钓鱼盘、面积逻辑矛盾）。并承认边界模糊性——以商圈为单位判断而非全城，避免把核心地段豪宅误判为异常。
R² 是多少？这个数算好吗？ 给出实测值，同时说明参照系：住房租金类截面数据 R² 在 0.6–0.75 属正常区间，因为房龄、采光、装修细节、房东心态等大量因素未进入模型。强调用 MAE 和误差区间比单看 R² 更有业务意义。
回归系数能说明因果关系吗？ 不能。系数只反映控制其他变量后的统计关联，且存在遗漏变量（房龄、通勤、学区）。要说"带电梯的房源挂牌单价高出 X%"，而不是"装电梯会导致租金上涨 X%"。
数据是怎么来的？合规吗？ 说明来源（公开数据集 / 遵守 robots 协议的限量采集），强调仅用于学习研究、不二次分发、作品中只公开聚合结果与代码。这是加分项——多数候选人答不上来。
这个分析最后谁在用？产生了什么价值？ 按三类角色回答：租客用它比价与筛房，房东用它定挂牌价并预估空置风险，平台用它做房源分层与价格异常识别。避免只说"做了可视化"。
执行建议

先跑通 Q1 与 Q2（描述性 + 诊断性），这两问的结论最容易讲清楚、也最快能出图，一周内可形成可展示的初版；Q5 的建模放在最后，它是锦上添花而非必需。作品集里最重要的不是模型精度，而是你能不能把"数据说了什么、所以应该怎么做"讲完整。
